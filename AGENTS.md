# Project Instructions

Elite Knight Co., Ltd. (`wasinsri/elite-knight-website`) is a static, bilingual corporate consulting site for Data, AI, Governance, Cybersecurity, Digital Trust, Digital Excellence, Management Consulting, and Strategic PMO. The site uses HTML, `assets/site.css`, and `assets/site.js`; there is no framework, package manager, or build step. Main pages are `index.html`, `about.html`, `services.html`, `insights.html`, `contact.html`, and `cookie-policy.html`. Thai articles live in `articles/`; English pages and articles live in `en/` and `en/articles/`.

## Architecture and page shell

- Preserve the static architecture. Edit existing HTML, CSS, and JavaScript directly. Keep reusable CSS in `assets/site.css` and browser behavior in `assets/site.js`; avoid new inline scripts except existing metadata, analytics, and JSON-LD patterns. Do not add dependencies, bundlers, or generated files without a user request.
- The Tailwind CDN compiler is gone. Utilities and preflight live at the top of `assets/site.css`, scoped with `:where(.ek-site)`. Define any new utility there; do not restore `cdn.tailwindcss.com` or introduce another reset or page-specific utility system.
- Start new pages from the closest existing page type. Use `articles/generative-ai-enterprise-safety-checklist.html` and `en/articles/generative-ai-enterprise-safety-checklist.html` as the Thai and English article templates. Preserve their shared shell and change only page-specific content, metadata, active navigation state, and relative paths. Do not rewrite repeated headers and footers when editing one page.
- Keep the desktop and mobile navigation in this order: Home, Expertise, Services, Insights, Contact. Only the current item has `active` and `aria-current="page"`. Preserve `data-mobile-menu-button`, `aria-expanded`, `aria-controls="mobile-menu"`, `data-mobile-menu`, and desktop/mobile TH/EN controls.
- Header navigation uses `assets/logo-192.jpg` from root pages, `../assets/logo-192.jpg` from `en/` and `articles/`, and `../../assets/logo-192.jpg` from `en/articles/`. Keep `brand-mark`; do not override header dimensions, `.ek-nav`, `.ek-nav > nav`, `.max-w-7xl`, `[data-mobile-menu-button]`, or the global reset on individual pages. `assets/logo.jpg` is used for metadata and structured data.
- Every public page needs the standard footer (company name, official LinkedIn and Facebook links, five site links, Cookie Policy, Bangkok address, hours, telephone, email), cookie banner (`data-cookie-banner`, `data-cookie-accept`, correct policy link), skip link to `#main-content`, focusable `<main tabindex="-1">`, and three favicon declarations (`favicon-192.png`, `favicon-32.png`, Apple touch icon). Never reference `favicon-master.png` from a page.
- Use relative paths. From `articles/`, assets begin `../assets/`; from `en/articles/`, they begin `../../assets/`. Do not use root-relative paths without confirmed root hosting.
- All HTML pages must use one shared cache version for both `assets/site.css` and `assets/site.js`. When either shared asset changes, update the version across every HTML file. A page-specific version blocks release.

## Language, content, and visual style

- Thai is the default (`lang="th"`). Public Thai and English pages use separate URLs and `data-language-routing="true"`; TH/EN controls link to the matching page. Root Thai pages link to `en/<page>.html`; English root pages link to `../<page>.html`; article pairs use their correct relative paths. Keep reciprocal `hreflang` and language-specific canonical URLs.
- Where present, update paired `data-th`/`data-en`, `data-aria-th`/`data-aria-en`, and `data-title-th`/`data-title-en` values together. `assets/site.js` replaces text from these attributes only on pages without URL routing; it stores the selected language as `ekLanguage`.
- Use the established teal, slate, white, and neutral palette. Keep cards restrained and responsive. Preserve keyboard access, accurate ARIA state, visible focus, meaningful image `alt` text, and reduced-motion behavior. Use inspectable, relevant imagery rather than abstract filler when the subject calls for it.
- Keep company identity and contact details consistent: `Elite Knight Co., Ltd.`, `บริษัท เอลีท ไนท์ จำกัด`, Mobile `063-664-1555`, `info@ek.co.th`, and the existing Bangkok address. Use only official social URLs.

## Articles and Insights

- Every new article needs a Thai/English pair, approximately 4,000–6,500 visible editorial characters per language, and one visible FAQ with exactly five substantive question-and-answer items. Count headings and visible FAQ answers, excluding markup, metadata, navigation, footer, cookie banner, share labels, and whitespace. Do not publish outside this range without user approval. Keep complete `data-th`/`data-en` text and align both FAQ questions and answers with FAQPage JSON-LD.
- Each article page needs LinkedIn, Facebook, and X share buttons above the body. Each article card on `insights.html` and `en/insights.html` needs exactly three `.share-button` links and shared `.article-card` styling; do not add card-specific spacing that shifts actions vertically.
- Add one card to each main Insights grid (`data-insights-grid` inside “All Articles”), never to `insight-categories`. Append it as the final source card: `assets/site.js` reverses cards so the new card displays first. Add the slug and categories to `articleCategories` in `assets/site.js` and verify both language filters.
- Give each new article pair one unique, relevant 16:9 `images.unsplash.com` thumbnail, shared by both cards, with descriptive Thai and English `alt` text. Add both canonical URLs and accurate `<lastmod>` dates to `sitemap.xml`.

## SEO, analytics, and internal links

- Keep each page focused on one search intent. Align title, meta description, canonical, Open Graph, Twitter card, favicon metadata, visible copy, and JSON-LD. State the audience, business outcome, and Thailand or Bangkok context where relevant; avoid keyword stuffing and thin service pages.
- Home and contact pages use `ProfessionalService` or `Organization` data; service landings use `Service`, `FAQPage`, and `BreadcrumbList`; articles use `BlogPosting` or `Article`, `FAQPage` where relevant, and `BreadcrumbList`. Keep article dates, `mainEntityOfPage`, image, section, publisher, and author accurate. The article author is Wasin Srisawat, Consultant (`https://www.ek.co.th/about.html#wasin-srisawat`); publisher is the organization. Omit placeholder `sameAs` URLs.
- Keep `sitemap.xml` current for added, removed, renamed, or materially updated pages. Link services to relevant insights and contact, articles to relevant services, and home/services overview to dedicated service pages. Service pages should explain the problem, outcomes, who the service is for, capabilities or frameworks, FAQ, and next step. Use concise visible summaries and buyer terms such as AI consulting, Data Governance, AI Governance, Cybersecurity Consulting, Digital Transformation Consulting, Management Consulting, Strategic PMO, Portfolio Management, ISO/IEC 42001, ISO/IEC 27001, NIST, COBIT, and ITIL where relevant.
- Keep analytics behind `ekCookieConsent`: copy the `let analyticsLoaded` pattern from `index.html`; never add a direct Google Tag Manager script tag. Preserve the cookie notice and policy behavior.

## Verification and publishing

- For a small copy or asset change, check affected pages and behavior. For layout or shared CSS/JavaScript changes, inspect representative pages at desktop and mobile widths, test affected TH/EN links and interactions, and check the browser console. Verify relative links and paths, especially in both article directories. Parse affected JSON-LD when metadata changes.
- For a new or substantially changed page, compare its shell with the template. At 1440px, compare header bounds and logo/menu positions with an existing page; at 390px, confirm the 76px header and stable logo/menu button positions.
- For a new article pair, verify per file: one cookie banner, three favicon declarations, four language controls, one mobile-menu button and menu, three article share buttons, and one standard footer. Check that both Insights pages have equal card counts and three share links per card; the new card appears once in the main grid, last in source order, first in the default browser view, and in its category filter.
- Before publishing an article pair, run `python3 tools/check-consistency.py --article articles/<slug>.html en/articles/<slug>.html`. This checks editorial length and five visible FAQ questions against FAQPage JSON-LD. Review FAQ answers manually; the script does not compare them.
- Before any publish, run `python3 tools/check-consistency.py` and `git diff --check`. The first command checks asset versions, required shell markers, consent-gated analytics, Tailwind CDN absence, CSS classes, JSON-LD syntax, relative paths, image `alt`, and page-level `data-th`/`data-en` counts. Inspect attribute pairs on changed elements yourself. CI runs the same command without `--article` in `.github/workflows/site-checks.yml`.
- When asked to upload, publish, or push to GitHub, use the GitHub connector by default; use local `git push` only if explicitly requested or the connector is unavailable. Confirm the target branch and exact files, exclude unrelated changes, then verify the uploaded files on GitHub and report the branch or commit.
