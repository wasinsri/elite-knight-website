## 2. คะแนนแตกรายเมตริก

PageSpeed ให้น้ำหนักแต่ละเมตริกต่างกัน ตารางนี้คือจุดที่คะแนนหายจริง ๆ

| เมตริก | ค่าที่วัดได้ | น้ำหนักเต็ม | ได้จริง | **หายไป** |
|---|---|---|---|---|
| First Contentful Paint (FCP) | 2.7 s | 10 | 6 | **−4** |
| Largest Contentful Paint (LCP) | 2.9 s | 25 | 20 | **−5** |
| Speed Index (SI) | 4.4 s | 10 | 7 | **−3** |
| Total Blocking Time (TBT) | 0 ms | 30 | 30 | 0 ✅ |
| Cumulative Layout Shift (CLS) | 0 | 25 | 25 | 0 ✅ |

**อ่านผล:** 12 คะแนนที่หายไปอยู่ที่ FCP + LCP + SI ทั้งหมด แปลว่าปัญหาคือ *เบราว์เซอร์เริ่มวาดหน้าช้า* ไม่ใช่ *หน้าหนักหรือกระตุก* — งานที่ต้องแก้จึงแคบและชัดเจนมาก

ถ้าดัน FCP ลงเหลือ ~1.8 s และ LCP ~2.3 s จะได้คะแนนกลับมาประมาณ 8–10 จุด → **Performance ~96–98**

## 3. สาเหตุราก (Root Cause)

### 3.1 CSS บล็อกการเรนเดอร์ — ตัวการหลักของ FCP
- `assets/site.css` ขนาด **60 KB ดิบ / ~12 KB gzip** โหลดแบบ `<link rel="stylesheet">` ธรรมดา
- Lighthouse ระบุ: render-blocking **190 ms**, critical path latency รวม **589 ms**
- เบราว์เซอร์ต้องรอไฟล์นี้จบก่อนถึงจะวาดพิกเซลแรกได้ — FCP จึงค้างที่ 2.7 s

### 3.2 LCP element คือรูป hero จาก Unsplash (โดเมนภายนอก)
- ไฟล์ AVIF 480w ขนาด **38.4 KB** — Lighthouse บอกว่าบีบอัดได้อีก **12.3 KB**
- ต่อให้ใส่ `preconnect` + `fetchpriority="high"` แล้ว ยังต้องเสีย DNS + TLS handshake ไปที่ `images.unsplash.com` ก่อนเริ่มดาวน์โหลด
- ทั้งไซต์พึ่ง Unsplash หนัก: หน้าแรก 3 จุด, `/insights.html` 20 จุด, บทความทุกหน้า 3 จุด

### 3.3 Google Fonts เป็นโดเมนที่สาม
- `Inter` + `Noto Sans Thai` (4 น้ำหนัก ทั้งคู่) โหลดจาก `fonts.googleapis.com` → `fonts.gstatic.com`
- Noto Sans Thai เป็นฟอนต์ตัวใหญ่ และการโหลดข้ามโดเมนเพิ่ม round-trip ให้ Speed Index

### 3.4 ไฟล์ยังไม่ minify
- CSS: Lighthouse ประเมินลดได้อีก **~2 KB**
- JS: `assets/site.js` 20 KB ดิบ / ~5.6 KB gzip ยังไม่ผ่าน minifier

### 3.5 Cache TTL สั้น (10 นาที) — แก้ไม่ได้ ให้ยอมรับ
- ไฟล์ static ทั้งหมดได้ TTL 10 นาที (savings 22 KB)
- ไซต์โฮสต์บน **GitHub Pages** (มีไฟล์ `CNAME`) ซึ่ง **ไม่เปิดให้ตั้ง cache header เอง**
- กระทบเฉพาะ repeat visit ไม่กระทบคะแนน first-load — **ไม่คุ้มที่จะย้ายโฮสต์เพื่อเรื่องนี้อย่างเดียว**

### 3.6 เฉพาะ `/insights.html`
- พบ **forced reflow** และ **long main-thread task 1 รายการ**
- น่าจะมาจาก `initializeInsights()` ที่วนอ่าน/เขียน DOM ของการ์ดบทความ 18–20 ใบตอน init
- ตอนนี้ยังไม่กระทบคะแนน (TBT = 0) แต่ควรเก็บกวาดไว้ก่อนบทความเพิ่มจำนวน

## 4. แผนแก้ไข เรียงตามความคุ้มค่า

| # | สิ่งที่ทำ | ผลที่คาด | ความเสี่ยง | แรง |
|---|---|---|---|---|
| 1 | **Inline critical CSS** (above-the-fold ~6–8 KB) ใน `<head>` แล้วโหลด `site.css` ที่เหลือแบบ async | FCP −0.6 ถึง −0.9 s | ต่ำ–กลาง | กลาง |
| 2 | **Self-host รูป hero** เป็น AVIF ขนาดพอดี ไว้ใน `assets/img/` | LCP −0.4 ถึง −0.6 s, ตัด 1 โดเมน | ต่ำ | ต่ำ |
| 3 | **Self-host ฟอนต์** (`.woff2` subset ไทย+ละติน) + `font-display: swap` | SI −0.3 ถึง −0.5 s, ตัด 2 โดเมน | ต่ำ | กลาง |
| 4 | **Minify CSS + JS** ใน GitHub Actions ที่มีอยู่แล้ว (`site-checks.yml`) | −8 KB transfer | ต่ำมาก | ต่ำ |
| 5 | ลดน้ำหนักฟอนต์จาก 4 เหลือ 3 (400/600/700) | ลด payload ฟอนต์ ~25% | ต่ำ | ต่ำมาก |
| 6 | เก็บ forced reflow ใน `initializeInsights()` (อ่าน DOM ให้จบก่อนค่อยเขียน) | กัน TBT โตในอนาคต | ต่ำ | ต่ำ |
| 7 | Cache TTL | — | — | **ข้าม** (GitHub Pages ทำไม่ได้) |

**ทำแค่ข้อ 1–4 ก็น่าจะพา Performance ขึ้นไปที่ ~95+ แล้ว**

## 5. ข้อสังเกตสำหรับการทำจริง

- หน้าทั้งหมด **68 ไฟล์ HTML** (ไทย 34 + อังกฤษ 34) ใช้ `<head>` โครงเดียวกันและ `site.css` ตัวเดียวกัน → แก้ครั้งเดียวได้ผลทั้งไซต์ แต่ต้องแก้ทุกไฟล์พร้อมกันด้วยสคริปต์ ไม่ใช่มือ
- มี query string `?v=20260923-ux-6` เป็น cache-buster อยู่แล้ว — ถ้าแก้ CSS/JS ต้องเลื่อนเวอร์ชันทุกไฟล์พร้อมกัน
- หน้าบทความใช้รูป Unsplash เป็น `og:image` ด้วย — ถ้าจะ self-host ต้องเปลี่ยน meta tag ตามด้วย
- CLS = 0 และ TBT = 0 อยู่แล้ว **อย่าแตะโครง layout หรือ lazy-loading ที่ทำไว้ดีแล้ว** ระหว่างแก้

## 6. ข้อจำกัดของรายงานนี้

- ทดสอบจริง 2 หน้า (หน้าแรก + insights) ตามที่ตกลงกัน หน้าที่เหลือวิเคราะห์จากโครงสร้างโค้ด ซึ่งใช้ `<head>`, CSS และ JS ชุดเดียวกันทั้งหมด จึงคาดว่าผลใกล้เคียงกัน (หน้าบทความอาจต่ำกว่าเล็กน้อยเพราะ HTML ใหญ่กว่า 80–112 KB)
- ยังไม่มีข้อมูล CrUX (ผู้ใช้จริง) — PSI แสดง "No Data" แปลว่า traffic ยังไม่ถึงเกณฑ์ ตัวเลขทั้งหมดจึงเป็น lab data
- ยังไม่ได้ทดสอบ desktop form factor
